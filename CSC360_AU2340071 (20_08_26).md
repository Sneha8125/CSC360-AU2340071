Reflection: Computer Graphics & Digital Image Processing

In this class, I learned that a reflection is not simply about summarizing all of the work done during class. Instead, a reflection should state the lessons learned from the process, concepts learned during the class, and how they can be beneficial in future endeavors. It needs to be done in a professional, clean, and concise way to ensure that another individual is able to comprehend my learning.

One interesting topic covered in this class was the use of proper naming conventions when working on GitHub projects. During the class, I realized that names need to be consistent, meaningful, and readable. One convention that I particularly enjoyed learning about was the use of a hyphen (-) rather than an underscore (_) when needed. This is because names become easier to understand when using such a convention.

In addition, I learned to select the right file format to write the documentation. In case of a reflection, we need to write it in a .md (Markdown) file instead of the .txt file. The reason is that the Markdown format allows us to write headings, lists, code blocks and many other formatting options. Moreover, Markdown files are nicely formatted on GitHub.

One more important thing which I learned is that our reflection shouldn't be a copy of our class notes and the list of steps we had done. Reflection must concentrate on our understanding and learnings from the class. It must cover all key concepts while describing them in our own words along with the description of the problems faced (if any) and their solutions.

In conclusion, in this session, I realized that proper documentation is one of the most important parts of doing the technical stuff. Following naming conventions, selecting the right file format, organizing our GitHub repository and writing our reflections in the right format will help us to look professional. These skills will also be very helpful in our future academic projects and internships.
