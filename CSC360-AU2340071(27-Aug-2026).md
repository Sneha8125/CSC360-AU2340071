## 1. Introduction to JavaFX

- I was introduced to **JavaFX**, a Java framework used for developing graphical user interfaces and interactive applications.
- I learned that JavaFX provides different components and modules that help in building a complete GUI application.
- The session began with **launching a JavaFX application**, which helped me understand the basic process of running a GUI-based Java program.
- I also learned that JavaFX applications require proper **configuration in IntelliJ IDEA** and correct project dependencies to run successfully.

---

## 2. Running JavaFX with Maven

- I learned how Maven can be used to run a JavaFX application through the command line.
- The command discussed in class was based on the JavaFX Maven plugin, using `javafx:run` to launch the application.
- Maven makes it easier to manage the project because the required libraries and dependencies can be specified in the `pom.xml` file.
- This showed me how an application can be built and executed in a consistent way rather than depending only on IDE-specific settings.

---

## 3. Maven Repository and Group ID

- I learned about the concept of a **repository** in Maven, where project dependencies and packages can be stored and retrieved.
- Maven uses a **Group ID** to identify the organization, group, or namespace to which a project belongs.
- I understood that a proper Group ID and project configuration help Maven identify and manage different projects and their dependencies.
- The concept of the **default repository** also helped me understand where Maven looks for required dependencies before downloading them.

---

## 4. JAR Files and ZIP Files

- I learned about **JAR (Java Archive)** files and their purpose in Java applications.
- A JAR file can package compiled Java classes and other project resources into a single archive.
- I also learned that a JAR is structurally similar to a ZIP file because both use archive-based packaging.
- However, a JAR is specifically designed for Java applications and can contain compiled `.class` files and other resources.
- An important point I learned is that a JAR file itself does **not automatically store all external dependencies** required by an application.
- This made me understand why dependency management through tools such as Maven is important when building and distributing Java applications.

---

## 5. CI/CD and Dependencies

- I was introduced to the idea of **CI/CD (Continuous Integration and Continuous Delivery/Deployment)** and its connection with software development.
- Continuous Integration involves regularly integrating changes made by developers and checking whether the project still builds and works correctly.
- Dependencies are also an important part of CI/CD because the build environment needs access to the required libraries and versions.
- This helped me understand how automated development pipelines can reduce manual effort and identify problems earlier.

---

## 6. Integration and Deployment

- I learned the difference between **integration** and **deployment** in a software project.
- Integration involves bringing changes from different sources together and making sure that the complete project works correctly.
- For example, a server can fetch the latest changes, integrate them with the existing project, and compile the updated code.
- Deployment refers to moving the completed application or build to a **remote server or production environment** where it can be used.
- I understood the general flow as:
  - **Server fetches the changes**
  - **Changes are integrated and compiled**
  - **The application is deployed to the remote server**
- This gave me a basic understanding of how source code moves from development to a usable application.

---

## 7. Properties and Character Sets

- I learned about **properties and character sets**, especially the use of **UTF-8**.
- UTF-8 is a character encoding that allows text from many languages and character sets to be represented.
- I understood that choosing an appropriate character set is important when applications need to handle different types of text.
- Character encoding can also have practical effects related to **time, speed, memory usage, and other resource considerations**.
- This showed me that even small configuration properties can affect how a software system processes and stores information.

---

## 8. Double vs Float and Data Types

- I learned about the difference between the **double** and **float** data types in Java.
- Both are used to represent decimal or floating-point numbers, but they provide different levels of precision and require different amounts of memory.
- This helped me understand that choosing a data type should depend on the requirements of the application rather than using one type everywhere.
- I also learned through examples that even when storing a simple value, the selected data type can have an effect on **memory usage and overall cost**.
- Therefore, data type selection is an important part of writing efficient programs.

---

## 9. Compiler Release and Compatibility

- I learned about the **compiler release** concept and how it can combine source and target compatibility requirements.
- The `--release` option can be used to specify the Java platform version against which the source code should be compiled.
- I understood the importance of keeping the **source version and runtime version** compatible.
- The source version determines which language features can be used, while the generated target bytecode needs to be compatible with the intended Java runtime.
- This concept helped me understand why a program compiled with a newer Java version may not run correctly on an older Java runtime.

---

## 10. Source Version and Target Version

- I learned that the **source version** controls the Java language features that the compiler accepts.
- For example, using a particular source version means that the corresponding language features are available to the programmer.
- The **target version** is related to the version of Java for which the compiled bytecode is intended.
- I understood that these settings are important for maintaining **compatibility** across different Java environments.
- This also helped me connect compiler settings with the type of Java version used to compile and execute a project.

---

## 11. Java 17 and Language Features

- I learned about **Java 17** and its relationship with language features, compiler settings, and runtime compatibility.
- A project can specify a particular Java version so that the source code, compiler, and runtime environment work together correctly.
- This is particularly important when a project is developed on one computer but needs to be built or executed on another machine.

---

## 12. JUnit and Testing

- I was introduced to **JUnit**, a commonly used framework for testing Java programs.
- Testing helps validate whether individual parts of a program are producing the expected results.
- I understood that testing is an important part of software development because it helps identify errors before the application is delivered.
- JUnit is especially useful for **unit testing**, where individual methods or components can be tested independently.

---

## 13. Validation and Testing

- I learned that **testing is a form of validation** used to check whether a program behaves according to its requirements.
- Proper testing helps identify defects and provides confidence that the implemented functionality is working correctly.
- Testing can be performed at different levels depending on whether we are checking individual components, the complete application, or the user interface.

---

## 14. Headless Testing

- I learned about **headless testing**, where tests are executed without displaying a graphical user interface.
- This is useful when testing can be performed without directly interacting with the visual components of an application.
- Headless testing can be useful in automated environments such as servers and CI/CD pipelines because a physical display is not required.
- It helped me understand how software can be tested automatically even when a GUI is not visible.

---

## 15. GUI Testing

- I learned about **GUI testing**, which focuses on checking whether graphical components behave correctly.
- GUI testing can involve checking buttons, menus, input fields, windows, and other interactive components.
- This is particularly relevant to JavaFX applications because the correctness of a GUI depends not only on the underlying code but also on how the user interacts with the application.

---

## 16. Unit Testing

- I learned that **unit testing** focuses on testing small and independent parts of a program.
- Instead of testing the entire application at once, individual methods or components can be tested separately.
- This makes it easier to identify the exact location of an error and helps maintain the quality of the project as the codebase grows.

---

## 17. JavaFX Model, Version and Modules

- I learned about the basic **JavaFX model, versions, and modules** used when developing JavaFX applications.
- JavaFX is divided into modules that provide different functionalities required by an application.
- Correctly selecting and configuring the required version and modules is important for successfully running a JavaFX project.
- This helped me understand why JavaFX projects require appropriate configuration instead of simply writing GUI code without considering the supporting modules.

---

## 18. JavaFX Controls

- I learned about **JavaFX controls**, which are reusable GUI elements used to interact with users.
- Examples include **buttons, trees, and other interface components**.
- These controls make it possible to build structured and interactive graphical applications.
- I understood that GUI development involves combining different controls according to the requirements of the application.

---

## 19. FXML

- I was introduced to **FXML**, which provides a declarative way of creating JavaFX user interfaces.
- Instead of creating every GUI component directly through Java code, the structure of the interface can be described using FXML.
- This helps separate the **user interface design from the application logic**, making the project easier to organize and maintain.
- Learning FXML gave me another approach to designing JavaFX interfaces apart from writing everything programmatically.

---

## 20. Web and Media in JavaFX

- I also learned that JavaFX provides support for **web and media-related functionality**.
- The Web component can be used to incorporate web-based content into a JavaFX application.
- Media-related features can be used to work with audio and video content.
- This showed me that JavaFX is not limited to basic buttons and windows but can support richer and more interactive applications.
