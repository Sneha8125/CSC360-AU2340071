Reflection: Streaming, Rendering, Databases and Graphics

## 1. Streaming
- I learned that streaming is a method of continuously receiving and processing data, such as audio or video, without requiring the complete content to be downloaded first.
- I understood that downloading is generally finite because the complete file is transferred and stored, whereas streaming can continue for an indefinite period as new data becomes available.

## 2. Video and Graphics
- I learned that graphics generally represent visual objects or images, while video is a continuous sequence of visual frames displayed over time.
- This helped me understand why video applications require continuous data processing and transmission.

## 3. Sample, Population and Expectation
- I understood that a population represents the complete set of observations being studied, while a sample represents a smaller portion selected from that population.
- I learned that the expectation of X represents the average or expected value of a random variable.
- I also learned that variance can be expressed using expectations as:
  
  `Var(X) = E(X²) - [E(X)]²`
  
- This connected statistical concepts with streaming, where data can arrive continuously and its properties may need to be calculated without storing the complete dataset.

## 4. XML and SVG in Graphics
- I learned that XML is connected to computer graphics because it provides a structured way of representing data and defining elements.
- SVG uses XML-based syntax to describe vector graphics, allowing graphical objects to be represented using structured elements.
- I also learned about tools such as Adobe Illustrator that can be used to create and work with SVG graphics.

## 5. Networking and Graphics
- I understood that networking is important in graphics applications because graphical content often needs to be transferred between a server and a client.
- This is particularly relevant for web applications, online media, cloud-based graphics and applications that retrieve visual data from remote servers.

## 6. Server-Side and Client-Side Programming
- I learned that server-side programming executes on the server and is responsible for tasks such as processing requests, authentication and database operations.
- Client-side programming executes in the user's browser and is mainly responsible for creating interactive interfaces and responding to user actions.
- I understood that both approaches are required because modern applications need server processing as well as responsive user interfaces.
- Next.js helped me understand server-side rendering and how pages can be prepared on the server before being delivered to the client.
- I also learned that rendering refers to the process of generating the visual output that is presented to the user.
- Server-side rendering can improve initial loading and provide content from the server, while client-side rendering can provide highly interactive interfaces after the page is loaded.

## 7. JavaScript and Web Applications
- I learned that JavaScript plays an important role in client-side programming by making web pages interactive.
- I also understood that different parts of an application may use different execution environments depending on their requirements, such as displaying landing-page content or handling signup and login operations securely on the server.

## 8. Databases and Graphics
- I understood that databases and graphics are connected when graphical applications retrieve stored data and represent it visually.
- I learned about relational databases and how structured data can be stored using tables.
- I was also introduced to Neo4j and Cypher, which helped me understand graph databases and how relationships between connected data can be represented and queried.

## 9. Internationalization
- I learned that internationalization is the process of designing software so that it can support different languages, regions, formats and cultural requirements without requiring major changes to the application.

## 10. AWT
- I learned about AWT (Abstract Window Toolkit), a Java framework used for creating graphical user interfaces.
- I understood that it is called "Abstract" because it provides a common set of GUI components and interfaces that work with the underlying operating system's windowing system.

## Overall Reflection
- This session helped me understand how computer graphics connects with streaming, statistics, networking, web technologies and databases.
- I gained a broader understanding of how visual applications receive data, process it, store it and finally render it for users.
- The session also helped me connect theoretical concepts such as expectation and variance with practical applications involving continuously arriving data.
